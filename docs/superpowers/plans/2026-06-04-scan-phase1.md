# Scan — Phase 1 (Simulated Barcode + Add-Item Pipeline) Implementation Plan

> **For agentic workers:** Implement task-by-task with TDD. Steps use checkbox (`- [ ]`) syntax. Spec: `docs/superpowers/specs/2026-06-04-scan-buttons-design.md` (decisions resolved in §8).

**Goal:** Make the two "New shop" buttons functional in a simulated, Expo-Go-friendly way: tapping **Scan Barcode** lets the user pick a photo, then the app simulates a product lookup and lets them confirm (quantity defaults to the whole package) and add it to the active meal prep cycle. Add a **stocked-vs-budget** bar and a **floating "+" add menu** for cycles that already have items. **Scan Receipt** stays a "coming soon" stub (Phase 2).

**Architecture:** Real camera / barcode-decode / Open Food Facts / vision-LLM are deferred. v1 uses `expo-image-picker` for the "upload a photo" step, then returns a mock product from a built-in catalog. Pure logic (nutrition math, random product pick) is isolated and unit-tested; the picker side-effect lives in a thin `src/services/scan.ts` that no test imports. The detail area: empty cycle → existing `NewPeriodPanel` (its two buttons now call real handlers); non-empty cycle → `BudgetBar` + `MealPrepDetail` + `AddFab`. An `AddItemSheet` modal handles confirm/manual-entry for both states.

**Tech Stack:** Expo SDK 54, React Native, `expo-image-picker` (new dep), Jest + @testing-library/react-native.

---

## Scope / YAGNI

**In scope:** simulated barcode scan (photo pick → mock product → confirm → add), manual-entry fallback inside the sheet, stocked-vs-budget bar, floating "+" add menu (rotate-to-×) for non-empty cycles.

**Out of scope (do NOT build):** real camera, real barcode decoding, real Open Food Facts calls, receipt OCR / vision-LLM, editing/deleting existing items, persistence, macros UI. Scan Receipt → "Coming soon" Alert.

import { FoodItem } from '../types'

export function kcalForWeight(kcalPer100g: number, weightG: number): number {
  return Math.round((kcalPer100g * weightG) / 100)
}

export function totalKcal(items: FoodItem[]): number {
  return items.reduce((sum, item) => sum + item.kcal, 0)
}

export function cycleBudget(days: number, dailyGoal = 2000): number {
  return days * dailyGoal
}
```

import React, { useRef, useState } from 'react'
import { View, Text, TouchableOpacity, Animated, StyleSheet } from 'react-native'

type Props = {
  onScanBarcode: () => void
  onScanReceipt: () => void
}

export default function AddFab({ onScanBarcode, onScanReceipt }: Props) {
  const [open, setOpen] = useState(false)
  const rotate = useRef(new Animated.Value(0)).current

  function toggle(next: boolean) {
    setOpen(next)
    Animated.timing(rotate, {
      toValue: next ? 1 : 0,
      duration: 150,
      useNativeDriver: true,

  function choose(fn: () => void) {
    toggle(false)
    fn()

  return (

import * as ImagePicker from 'expo-image-picker'
import { pickRandomProduct, Product } from '../mockProducts'

/**
 * Phase-1 simulation: let the user pick a photo (stand-in for pointing the
 * camera at a barcode), then return a mock product. Returns null if the user
 * cancels. Real camera + barcode decode + Open Food Facts come later behind
 * this same signature.
 */
export async function simulateBarcodeScan(): Promise<Product | null> {
  try {
    await ImagePicker.requestMediaLibraryPermissionsAsync()
    const result = await ImagePicker.launchImageLibraryAsync({
      mediaTypes: ['images'],
      quality: 1,
    })
    if (result.canceled) return null
    return pickRandomProduct()
  } catch {
    // If the picker is unavailable for any reason, fall back to a product so
    // the flow is still demoable.
    return pickRandomProduct()
  }
}
```
> Note: if the installed `expo-image-picker` version rejects `mediaTypes: ['images']`, use that version's documented form (e.g. `ImagePicker.MediaTypeOptions.Images`). Adjust to the installed API; do not break the build.
